# 五骰子房规概率判断器

这是根据本次用户确认的本地规则独立实现的离线计算器。直接用电脑或安卓浏览器打开同目录的 **五骰子判断器.html**。不需要安装 AI 模型、Python、Node 或联网；Node 仅供开发测试与重新生成页面。

## v1.2：新手流程和一轮决策

新网址：https://yiys54.github.io/five-dice-advisor/?v=1.2 。旧 chatgpt.site 链接不会自动更新。

- 打开后骰子为空，不把示例当成真实手牌；独立示例按钮明确标注。改动输入就收起旧建议，切阶段清空旧叫法。
- 庄家不用先猜叫法，直接得到推荐；仍可展开检查自己的数量、点数和斋/飞。模型推荐与正在检查的首叫分开标明。
- 两个目标：平均罚杯少，或本次结算不喝的概率高。直接给出完整叫法、当前开与继续叫的风险。
- 决策边界明确：继续叫后，下家立即普通开或批且自己接受。少杯目标取这两种结算的较高罚杯，再与现在普通开比较；没有模拟后续继续加叫，不能当作整局最优策略。
- 极小失败概率从整数补集直接计算，只有精确计数为零才显示0%或100%；排序和决策使用整数交叉相乘。
- 可选上家贡献假设：对指定上家的整手手牌筛选，所有跨点数、跨斋飞候选按同一事件重算，其余玩家独立卷积。默认关闭，只在接上家阶段生效，并显示无假设对照与假设的筛选强度。
- 显示全场有效数量均值与至少90%覆盖的离散中央区间；保留完整精确计数。
- 25项数学/房规测试通过（其中一项包含25组独立条件枚举核对）；另有15项CUA页面交互检查，473px视口无横向溢出。

## 已确定房规

- 每人5颗公平六面骰子，总人数含自己，支持2–20人。
- 非1点数数量≥6为飞，1可替目标；数量<6为斋，只数纯目标。
- 斋数量≥人数+1；庄家也不例外。5人及以上不存在非1点数的小于6的合法斋叫法。
- **斋和飞都允许同数量加点数**。原文“5个5斋不能接5个6斋”已由用户明确修正。
- 数量优先，数量相同按1＜2＜3＜4＜5＜6。叫1永远为斋，只数真实1；进入飞后不许再叫1，即使加数量。
- 任意5颗互不相同就整手重摇，直到不再是顺子。不是只重摇一次。默认去掉720种有序顺子手牌，保留7056/7776种结果。
- 飞：4个目标+1个1算6；5个目标算7；五个1对任意非1目标算7。
- 斋含叫1：只算真实目标。五个1在叫1时只算5。加成开局选定后自动结算，不由玩家在开盅后选择。
- 普通开半杯，批一杯，反批两杯；赢时自己罚杯为0。批后先给被批者应对机会，再开盅，不能先揭骰再决定反批。
- 仅当前下家能质疑上家；反批仅被批者可用，一层后结束。程序不加入连环批。
- 可选认输半杯默认关闭；界面可启用。连摇顺子自罚规则未启用，也未纳入期望罚杯。

## 准确算了什么

1. 枚举每位未知玩家整手骰子的7776种有序结果。
2. 删除应重摇的手牌。重复重摇直至有效，等价于对剩余有效手牌条件均匀分布。
3. 按飞/斋和整手豹子规则计算每手贡献分布。
4. 对未知玩家逐个做卷积，加入自己已知贡献。
5. 得出“全场有效数量≥叫数”的精确计数比。使用 BigInt 保留整数计数，显示百分比时才四舍五入。

因为整手重摇和豹子加成，同一手内骰子不能直接当作独立伯努利变量，不能原样使用常见二项分布计算器。

基础先验假设：只知道自己的手牌，其他玩家按公平骰独立摇出最终合法手牌。可选条件假设不是从叫牌自动推断出的事实。没有完整的对手叫牌历史、表情、出价策略或偏骰模型。故“精确”指**此概率模型下的精确计算**，不意味着真实对手在某次叫牌后的概率必然等于这个数。

## 动作损失

设当前叫法成立概率为p：

| 场景 | 自己喝的概率 | 自己预期罚杯 |
| --- | --- | --- |
| 我普通开上家 | p | 0.5p |
| 我批上家，上家不反批 | p | p |
| 我批上家，上家可能反批 | p | p+P(成立且反批)，介于p和2p |
| 我被批，接受批开盅 | 1-p | 1-p |
| 我被批，反批 | 1-p | 2(1-p) |
| 可选直接认输 | 1 | 0.5 |

只最小化自己的预期罚杯，且不计威慑和后续行为变化、对手没有认输选项时：开不劣于批，接受批不劣于反批。允许对手认输后，批可能诱发认输，不能直接沿用前一支配结论。p=0或p=1等边界可能打平。认输与接受批比较：p<0.5时认输平均罚杯较低；p>0.5时接受批较低；p=0.5打平。但认输的“喝的概率”永远是100%，所以最小概率与最小杯数不是同一个目标。

继续叫法成立概率为q时，如果**下家一定立刻普通开我**，自己预期罚杯为0.5(1-q)；如果立即批、自己接受，是1-q。v1.2的“平均少喝”取这两种立即结算中较高的1-q，与当前普通开的0.5p比较：q>1-0.5p时建议继续叫。“本次少输”则比较1-q与p：q>1-p时建议继续叫。相等按精确计数判定并提示并列。未知后续继续叫牌时不能假装这是整局最优解；默认建议是有边界的一轮比较。

例如2人、自己五颗1、上家8个6飞：普通开平均约0.4274杯，输局概率85.49%；续叫9个2飞，若立即被批并接受，平均约0.4739杯，输局概率47.39%。少杯推荐开，少输推荐继续叫。这是固定一轮情景的数学差异，并非实际长期胜率数据。

上家线索事件A为“上家对原叫法的手内贡献≥k”。对7056种有效手牌过滤出A；每个候选重新统计这同一批手牌的候选贡献，再卷积其余n−2人，分母为|A|×7056^(n−2)。不可能事件报错。k=0与无条件模型逐分数相等。条件导致的必真结论始终带假设限定。

页面搜索所有有意义数量（至全场最大有效贡献+1）及点数；超过理论最大量的叫法都必假，用一层代表即可。候选中相同成立概率优先较低数量、较低点数，这只是排序方式，不代表心理博弈最优。

## 开源项目调查（2026-10-20）

| 项目 | 核查结果 | 适配判断 |
| --- | --- | --- |
| [HighDiceRoller/icepool](https://github.com/HighDiceRoller/icepool) | MIT；纯Python，精确分数、重摇、骰池、sets/straights | 最适合做一般化概率后端；没有现成此房规和完整对手策略 |
| [ShellMonster/liars-dice-math](https://github.com/ShellMonster/liars-dice-math) | 飞/斋普通二项右尾概率参考；调查时没有明确LICENSE，部分完整引擎不在仓库 | 不能直接处理本规则的整手重摇、豹子；本实现未复制其代码 |
| [davidvoncos-bit/Liar-s-dice](https://github.com/davidvoncos-bit/Liar-s-dice) | MIT；双人五骰与若干启发式bot | 可参考游戏结构，但概率与策略不匹配本规则 |
| [facebookresearch/rebel](https://github.com/facebookresearch/rebel) | Apache-2.0；归档的自博弈框架，小规模吹牛骰示例 | 若将来研究博弈策略可参考；不是可直接套用的本地房规判断器 |

本实现没有引入或复制这些仓库代码，使用独立的五骰枚举和整数卷积。没有训练模型，不需要GPU。

## 验证与源码

- engine.js：纯计算模块，可用CommonJS或浏览器加载。
- page.template.html：界面模板；ui.js：输入、建议与展示。
- build.js：把引擎内嵌到单个可离线分发的HTML。
- test.js：针对整手重摇、加成、合法出价、二项特例交叉验证、卷积、边界与罚杯关系的测试。
- check-ui.js：供CUA浏览器调用的15项交互回归函数，使用现有标签，不启动其他浏览器。页面验证记录见 UI-CHECKS.md。

开发时：

```text
node test.js
node build.js
```
